# Buildergame file formats

Two file types let players share what they build. Both are plain JSON so they can be inspected,
diffed and generated by other tools. Every file carries a `format` string and an integer `version`;
readers reject unknown formats and versions rather than guessing.

## Coordinate system

- One voxel is one world unit. Coordinates are integers; a voxel at `(x, y, z)` occupies the half-open
  cube `[x, x+1) × [y, y+1) × [z, z+1)`.
- `+y` is up. The ground plane is `y = 0`; nothing can be placed below it.
- Rotations are quarter turns counter-clockwise around `+y` (as seen from above): `0`, `1`, `2`, `3`.
  One turn maps local `+x` toward `-z`. See *Rotation* below for the exact cell mapping.

## Structure file: `*.structure.json`

A structure is a finite voxel volume. Its `size` is its length (x), height (y) and depth (z) — always
the tight bounding box of the blocks it contains, so a saved structure never has empty margins.

```json
{
  "format": "buildergame.structure",
  "version": 1,
  "id": "4b9d0c62-3b6e-4d2e-9a1a-7f6bd0f4c1a1",
  "name": "Watchtower",
  "author": "Ada",
  "createdAt": "2026-09-27T10:15:00.000Z",
  "updatedAt": "2026-09-27T11:02:13.000Z",
  "size": { "x": 9, "y": 21, "z": 9 },
  "palette": [
    { "material": "stone", "color": "#8c8c8c" },
    { "material": "glass", "color": "#a8d8f0", "transparent": true },
    { "material": "lantern", "color": "#ffd27a", "emissive": true }
  ],
  "voxels": { "encoding": "rle-u16-base64", "order": "xzy", "data": "AAADAAEAAgD…" },
  "thumbnail": "data:image/jpeg;base64,…"
}
```

| Field | Meaning |
| --- | --- |
| `id` | Stable identifier, normally a UUID. Built-in examples use fixed ids such as `example-eiffel-tower`. Worlds reference structures by this id. |
| `size` | Extent along x, y, z. Each edge is at least 1; the in-game editor allows up to 128. |
| `palette` | Materials used, in first-use order. Voxel value `v` (1-based) refers to `palette[v-1]`; `0` is air. The colour is stored so a file still renders on a machine whose material list does not know that material id. |
| `voxels.order` | `xzy`: x varies fastest, then z, then y. Index = `x + size.x * (z + size.z * y)`. |
| `voxels.encoding` | `rle-u16-base64`: the voxel values are run-length encoded as little-endian `uint16` pairs `[value, runLength]` (run length 1–65535), then the byte stream is base64 encoded. |
| `thumbnail` | Optional data URL preview used by the library gallery. |

Readers must verify that the decoded voxel count equals `size.x * size.y * size.z` and that no voxel
value exceeds the palette length.

### Rotation

For a structure of size `(sx, sy, sz)`, a voxel at local `(x, z)` lands at the following cell of the
rotated footprint (whose min corner is the placement position):

| rotation | footprint | cell |
| --- | --- | --- |
| 0 | `(sx, sz)` | `(x, z)` |
| 1 | `(sz, sx)` | `(z, sx - 1 - x)` |
| 2 | `(sx, sz)` | `(sx - 1 - x, sz - 1 - z)` |
| 3 | `(sz, sx)` | `(sz - 1 - z, x)` |

`y` is unchanged. This is the mapping used both for rendering and for collision.

## World file: `*.world.json`

A world is one player's space: metadata plus where each structure instance sits. It references
structures by id and does not embed them.

```json
{
  "format": "buildergame.world",
  "version": 1,
  "id": "0d5e3f4a-…",
  "name": "Home",
  "createdAt": "…",
  "updatedAt": "…",
  "ground": { "material": "grass", "size": 1024 },
  "spawn": { "position": [0, 4, 12], "yaw": 0, "pitch": -0.15 },
  "structures": [
    { "id": "4b9d0c62-…", "name": "Watchtower", "file": "structures/4b9d0c62-….structure.json" }
  ],
  "placements": [
    { "id": "e1…", "structureId": "4b9d0c62-…", "position": [12, 0, -4], "rotation": 1 }
  ]
}
```

| Field | Meaning |
| --- | --- |
| `ground.size` | Edge length of the square ground centred on the origin. Placements must lie inside it. |
| `spawn` | Where the player starts: position and view angles in radians. |
| `structures` | Every structure referenced by a placement, with a display name and the path of its file relative to the world file. |
| `placements` | Instances. `position` is the min corner of the rotated footprint; `rotation` is 0–3. Placement ids are unique within a world. |

Placements never overlap: when a world is edited in game, a new placement is accepted only if no
solid voxel of it coincides with a solid voxel of an existing placement (bounding boxes may touch or
even interleave, as with two L-shapes).

## World bundle: `*.world.zip`

A zip archive that makes a world self-contained for sharing:

```
world.json
structures/<id>.structure.json   (one per referenced structure)
```

`world.json` is a world file whose `structures[].file` entries point at the archive paths. On import,
a structure whose id already exists locally is reused when its content is identical; if the content
differs it receives a fresh id and the world's placements are remapped, so nothing local is
overwritten. A world id that already exists locally likewise gets a fresh id.
